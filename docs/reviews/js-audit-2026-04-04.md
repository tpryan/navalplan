# JavaScript Code Audit — 2026-04-04

## Scope

Full audit of `code/app/frontend/js/main.js` (~4887 lines, ~60 functions) and supporting files (`code/app/frontend/js/share.js`, `jasmine/` test files).

---

## Summary

The codebase is functional and well-structured for a vanilla JS SPA. No confirmed dead functions were found, and all event listeners appear to be wired to existing elements. The main concerns are organizational (one very large function), a few memory leak risks, two uses of a deprecated browser API, and some duplicated logic that could be consolidated.

---

## Issues by Severity

### High — Memory Leak Risks

**1. `startHealthCheck()` — orphaned `setInterval`**

The health check sets up a recurring interval but never stores the return value, making it impossible to clear. If the function is ever called more than once (e.g., after re-auth), intervals stack up.

- Location: `startHealthCheck()` in `main.js`
- Fix: Store the interval ID and clear it before starting a new one.

```javascript
let healthCheckInterval = null;
function startHealthCheck() {
    if (healthCheckInterval) clearInterval(healthCheckInterval);
    healthCheckInterval = setInterval(...);
}
```

**2. SSE stream cleanup not guaranteed**

The EventSource stream opened by the local pilot/specialist flow is closed in the success/error callbacks, but if the component is navigated away from mid-stream, the stream may not be closed.

- Location: SSE handling in `main.js`
- Fix: Store the EventSource reference and close it in `clearRecommendations()` or the view teardown logic.

**3. Stop polling interval may orphan**

The polling interval used to check research status has the same risk — if the user navigates away while polling is active, the interval continues firing and may call state-mutating functions on stale data.

- Location: Research polling logic in `main.js`
- Fix: Store interval ID and clear it on view exit/navigation.

---

### Medium — Organizational Issues

**4. `initUI()` is 666 lines**

This single function wires all event listeners and contains significant inline logic. It is the largest single block in the file and makes it difficult to navigate or test individual UI sections.

- Recommendation: Extract logical groups into named setup functions:
  - `initVoyageListeners()`
  - `initMapListeners()`
  - `initResearchListeners()`
  - `initModalListeners()`
  - etc.
- `initUI()` becomes a coordinator that calls each.

**5. Duplicated tide chart logic**

`renderTideChart()` and `renderMiniTideChart()` share substantial logic for processing tide event data, building Chart.js datasets, and rendering axis labels. They differ mainly in canvas target and size.

- Recommendation: Extract a shared `buildTideChartConfig(events, options)` helper and call it from both.

**6. Duplicated geocoding logic**

Geocoding calls (converting a name/address to lat/lng) appear in multiple places rather than being routed through a single helper.

- Recommendation: Consolidate into a `geocodeLocation(query)` function.

**7. Chart.js instances not destroyed before re-render**

When tide charts are re-rendered (e.g., switching between stops), the previous Chart.js instance may not be explicitly destroyed. Chart.js warns about this and it can cause canvas reuse errors.

- Fix: Store chart instances and call `.destroy()` before creating a new one on the same canvas.

---

### Low — Deprecated APIs

**8. `document.execCommand('copy')` used in two places**

`execCommand` is deprecated and removed in some browser contexts. The Clipboard API is the modern replacement.

- Locations: Share link copy and itinerary copy buttons in `main.js`
- Fix:
```javascript
// Before
document.execCommand('copy');

// After
navigator.clipboard.writeText(text).catch(() => { /* fallback */ });
```

---

### Low — Minor / Style

**9. `calculateGeometryArea()` — possibly unused**

This function calculates the area of a GeoJSON polygon. Now that recommendation rendering has been converted from GeoJSON polygons to `AdvancedMarkerElement` icon markers, this function may no longer be called.

- Action: Verify with a grep before removing.

**10. `lastKnownResearchDone` may be partially redundant**

This state variable tracks whether full research has been run. It is used in a few conditional renders but its behavior may overlap with checking whether briefings exist on the stops themselves.

- Action: Low priority; revisit if research state logic is refactored.

**11. Heavy use of inline styles on dynamically generated HTML**

Most dynamic HTML (facility cards, recommendation items, voyage report sections) uses inline `style=""` attributes. This makes theming and overrides harder.

- Recommendation: Move repeated style patterns into named CSS utility classes. Not urgent — the current approach works.

---

## What Was NOT Found

- No event listeners wired to elements that don't exist
- No unreachable code paths (all branches appear reachable given normal user flows)
- No confirmed dead functions (all named functions appear to be called somewhere)
- No obvious XSS risks — `DOMPurify.sanitize()` is applied consistently to user-supplied and agent-generated content

---

## Recommended Priority Order

1. Fix memory leaks (health check interval, SSE stream, polling interval) — small, targeted fixes
2. Destroy Chart.js instances before re-render — small fix, eliminates console warnings
3. Replace `execCommand` with Clipboard API — small fix, future-proofs against browser deprecation
4. Extract `initUI()` into sub-functions — larger refactor, highest organizational value
5. Consolidate tide chart logic — medium refactor
6. Consolidate geocoding logic — medium refactor
7. Move inline styles to CSS classes — low urgency, nice to have
